# 企业招聘源维护工作区

这个目录用于把“招聘官网登记、公开岗位获取、字段核验、入库、导出、复核”拆成可并行交给不同 AI 的小任务。

## 目录约定

- `BATCH-01-confirmed-sources.md`：当前已经登记并至少有一部分岗位入库的来源。优先做增量维护。
- `BATCH-02-candidate-sources.md`：待核验的大中型企业官网，只能先登记，不能把候选地址当成已接入来源。
- `BATCH-03-small-company-onboarding.md`：中小企业接入方法，适合逐个核验自建站、飞书、北森、Moka、Greenhouse、Lever 等公开入口。
- `SOURCE_TASK_TEMPLATE.md`：给其他 AI 分派单个企业任务时复制的模板。
- `FIELD_AND_INGESTION_CONTRACT.md`：统一字段、质量门槛、数据库写入和 GitHub Pages 导出契约。

## 当前执行边界

1. 只处理公开可访问的校招页面，招聘类型最终只能是 `全职` 或 `实习`。
2. 必须精确到具体岗位详情页；只有“招聘计划/项目介绍/职位列表入口”不能作为岗位入库记录。
3. 页面明确出现 403、429、验证码、安全验证、登录墙时立即停止该来源并记录，不尝试绕过。
4. 单来源串行、低频访问；同一来源默认至少间隔 1 小时，不使用代理池、指纹伪装或猜测详情 URL。
5. 不允许用模型补写城市、学历、职位描述、招聘类型或投递链接。缺失字段进入隔离区，不能进入活动岗位。

## 推荐协作顺序

每个 AI 一次只领取一个企业任务：先核验官网和具体职位列表，再选择已有适配器或提交适配器需求，最后运行单来源采集、测试和导出。完成后必须回填模板中的“证据、结果、失败原因、下一步”。
