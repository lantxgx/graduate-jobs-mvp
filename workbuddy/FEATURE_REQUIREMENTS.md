# 牛投马面功能需求与 WorkBuddy 能力盘点单

版本：FR-1.0  
用途：让 WorkBuddy/HY3 先判断“原生能做、需要 Skill、需要连接器、需要人工、禁止执行”，再接受开发任务。

## 1. 能力状态枚举

WorkBuddy 必须给每一项填写且只能填写以下一种：

| 状态 | 含义 |
|---|---|
| `NATIVE` | 当前桌面端已经能读写本地文件并运行所需命令 |
| `NEED_SKILL` | 需要安装特定 Skill 才能稳定完成 |
| `NEED_CONNECTOR` | 需要浏览器、数据库、Git、终端等连接器 |
| `NEED_USER` | 必须由用户手动完成授权、选择、验证码或界面操作 |
| `CODEX_ONLY` | 风险或判断复杂度过高，保留给 Codex |
| `UNSUPPORTED` | 当前 WorkBuddy 环境无法完成 |
| `UNKNOWN` | 无法从当前界面确认，需做最小能力测试 |

禁止把“我觉得可以”写成 `NATIVE`。必须提供能力证据，例如实际读取文件、执行命令、看到退出码或成功控制浏览器。

## 2. 建议 Skill/连接器名称

名称可以因 WorkBuddy 平台不同而变化，但能力必须对应：

| 能力编号 | 所需能力 | 可能的 Skill/连接器 |
|---|---|---|
| CAP-01 | 读取/修改项目文件 | Workspace / Filesystem |
| CAP-02 | 执行 PowerShell、Python、Node 命令 | Terminal / Shell |
| CAP-03 | 查看本地 `127.0.0.1` 页面并操作 | Browser / Playwright / Computer Use |
| CAP-04 | 查看公开招聘网页和 XHR | Browser DevTools / Playwright Network |
| CAP-05 | 读取 SQLite，执行只读查询 | SQLite / Database Connector |
| CAP-06 | 比较代码改动 | Git / Diff Skill；项目无 Git 时需文件 Diff 能力 |
| CAP-07 | 解析 PDF/DOCX fixture | Documents / PDF Skill |
| CAP-08 | 处理 CSV/XLSX 企业候选表 | Spreadsheet Skill |
| CAP-09 | 长时间定时运行 | Scheduler / Automation / Task Runner |
| CAP-10 | 截图和视觉验收 | Browser Screenshot / Computer Use |

任何连接器都不得自动获得密钥、Cookie、浏览历史或账号权限。需要账号时必须标为 `NEED_USER`。

## 3. 完整功能需求

### FR-001 企业候选注册表

目标：收集大、中、小企业标准名称、官网、规模、行业、发现来源和证据 URL。

输入：公开企业目录、用户提供名单、CSV/XLSX。  
输出：候选表和企业主数据，不产生岗位。  
主要文件：`data/company_candidates.example.csv`、`crawler/company_directory.py`。  
质量门槛：企业别名归并，来源可追溯，候选企业不得显示为已有岗位。  
典型能力：CAP-01、CAP-02、CAP-08。  
HY3建议：本地 CSV 清洗可做；从互联网发现企业需要浏览器/搜索连接器并由 Codex复核。

### FR-002 官方招聘入口确认

目标：从企业官网导航到招聘/校招入口，记录最终域名和官方归属证据。

输入：企业官网。  
输出：`career_sources` 候选记录。  
门槛：必须能证明企业官网与招聘入口关系；短链接、第三方转载不能单独作为证据。  
典型能力：CAP-03、CAP-04、CAP-05。  
HY3建议：默认 `CODEX_ONLY`；WorkBuddy 没有浏览器抓取能力时不得执行。

### FR-003 ATS 类型识别

目标：识别飞书、北森、Moka、Greenhouse、Lever、Workday 或自建站。

输入：已确认官方招聘 URL、页面公开特征。  
输出：`ats_type`、适配器候选和证据。  
门槛：不得通过租户枚举或猜 URL。  
典型能力：CAP-04。  
HY3建议：有 HTML/URL fixture 时可 `NATIVE`；真实网页识别需要连接器。

### FR-004 离线 Fixture 制作

目标：把已合法获得的公开响应脱敏为本地测试样本。

输入：Codex 或用户提供的 JSON/HTML。  
输出：`tests/fixtures/<source-key>/`。  
门槛：移除 Cookie、Token、个人信息和不必要大字段；保留岗位解析所需结构。  
典型能力：CAP-01。  
HY3建议：适合 WorkBuddy 执行，但不能自行抓取原始响应。

### FR-005 ATS/企业适配器

目标：将公开列表和详情转换为标准中间对象。

输入：fixture、已有 adapter 接口。  
输出：`crawler/adapters/<source>.py` 和测试。  
门槛：适配器不直接写数据库；无详情 URL、计划卡、未知类型必须拒绝。  
典型能力：CAP-01、CAP-02。  
HY3建议：fixture 明确时适合；复杂签名/动态接口交给 Codex。

### FR-006 受控真实样本

目标：单来源串行获取最多 20 条真实岗位。

输入：完成 S1-S4 的来源。  
输出：crawl run、接受/隔离记录。  
门槛：403/429/验证码/登录墙立即暂停；不重试绕过。  
典型能力：CAP-02、CAP-04、CAP-05。  
HY3建议：默认 `CODEX_ONLY`；没有浏览器/网络连接器时 `UNSUPPORTED`。

### FR-007 字段标准化

目标：统一公司、城市、职能、岗位、全职/实习、学历、描述和要求。

输入：标准中间对象和 fixture。  
输出：标准岗位对象。  
门槛：遵守 `BASELINE.md` 第 4-6 节；不能由 AI 编造。  
典型能力：CAP-01、CAP-02。  
HY3建议：规则明确时适合 WorkBuddy。

### FR-008 质量门禁与隔离

目标：有效岗位进入 `jobs`，不合格观察进入隔离证据层。

输入：标准化对象。  
输出：active 或 quarantine。  
门槛：必填字段完整、详情 URL 具体、类型合法、非计划卡。  
典型能力：CAP-01、CAP-02、CAP-05。  
HY3建议：可以补测试；修改数据库门禁逻辑必须 Codex复核。

### FR-009 去重和增量更新

目标：同一岗位更新原记录，不产生重复。

身份优先级：`source_id + source_job_id` → 规范详情 URL → 稳定指纹。  
门槛：变化更新、重新出现恢复、详情失败不覆盖旧详情。  
典型能力：CAP-01、CAP-02、CAP-05。  
HY3建议：可写离线测试；真实数据库迁移为 `CODEX_ONLY`。

### FR-010 快照保护和下线

目标：防止空响应或结构变化清空岗位。

门槛：单次消失不下线；连续 3 次健康完整快照才 inactive；骤降 50% 保护。  
典型能力：CAP-01、CAP-02、CAP-05。  
HY3建议：适合补离线测试；修改生产数据需 Codex。

### FR-011 低频调度

目标：每轮只处理一个到期来源，维护锁、冷却和退避。

输入：`career_sources.next_run_at`。  
输出：单来源 run 和下次时间。  
门槛：Web 启动不采集；保护信号暂停；调度进程可停止和追踪。  
典型能力：CAP-02、CAP-05、CAP-09。  
HY3建议：脚本和测试可做；长时间无人值守需要 Automation 连接器。

### FR-012 岗位完整检索

目标：不需要画像即可搜索全部有效岗位。

输入：关键词和筛选项。  
输出：分页岗位列表。  
门槛：公司、城市、职能、岗位族、类型、学历筛选可组合；推荐不影响完整检索。  
典型能力：CAP-01、CAP-02、CAP-03。  
HY3建议：适合 WorkBuddy；视觉验收需本地浏览器连接器。

### FR-013 岗位详情和官方投递

目标：岗位卡显示描述/要求并跳转具体官方 URL。

门槛：链接必须来自来源证据；使用新标签、安全 rel；无详情不进入 active。  
典型能力：CAP-01、CAP-03。  
HY3建议：前端可做；外链真实性由 Codex验证。

### FR-014 收藏、忽略和已投递

目标：用户管理岗位行动状态。

门槛：忽略只影响默认推荐，不从完整检索删除；刷新后状态恢复。  
典型能力：CAP-01、CAP-02、CAP-03、CAP-05。  
HY3建议：适合本地开发和测试。

### FR-015 简历解析预览

目标：从 PDF/DOCX 提取候选能力证据，不长期保存原文件。

门槛：文件类型/大小校验；解析失败可理解；原始文件不入库；敏感内容不进日志。  
典型能力：CAP-01、CAP-02、CAP-07。  
HY3建议：fixture 测试可做；真实简历需要用户授权和文档 Skill。

### FR-016 结构化画像

目标：保存用户确认的能力证据和求职意愿。

门槛：简历不自动代填求职意愿；比例合计 100%；允许删除。  
典型能力：CAP-01、CAP-02、CAP-03、CAP-05。  
HY3建议：适合本地开发，测试不要覆盖用户真实画像。

### FR-017 可解释推荐

目标：主攻、目标企业、相邻、探索四类召回并解释匹配维度。

门槛：完整检索保留；销售噪音受控；用户点名企业单独召回；相邻岗位说明转型距离；AI 不编造资格。  
典型能力：CAP-01、CAP-02、CAP-05。  
HY3建议：机械测试可做；策略和权重由 Codex审核。

### FR-018 数据管理页

目标：运营者查看企业入口、接入状态、运行、质量和隔离证据。

门槛：普通读取/筛选不触发采集；状态中文可读；内部原因保留可追踪代码。  
典型能力：CAP-01、CAP-02、CAP-03。  
HY3建议：非常适合 WorkBuddy，当前后续任务 WB-001 属于这一项。

### FR-019 运行可观测性

目标：每次真实运行记录发现、新增、更新、隔离、停止原因和保护动作。

门槛：日志不得含密钥、Cookie 或完整敏感响应；空调度也有明确事件。  
典型能力：CAP-01、CAP-02、CAP-05。  
HY3建议：日志格式和页面展示可做；真实运行判断由 Codex。

### FR-020 服务运维

目标：可重启 Web、启动/停止单一调度树、检查健康。

门槛：只操作项目进程；不得按进程名批量杀死 Python；PID 必须验证命令行。  
典型能力：CAP-02、CAP-09。  
HY3建议：需要终端连接器；进程控制改动必须 Codex验收。
