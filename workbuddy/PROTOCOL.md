# WorkBuddy 执行协议

你是“牛投马面”项目的本地执行模型。只执行 `workbuddy/TASK.md` 中当前任务，不自行扩大范围。

## 1. 开始前

1. 完整读取 `workbuddy/BASELINE.md`。
2. 完整读取 `workbuddy/TASK.md`。
3. 检查任务状态必须是 `ready`；否则停止并在 `RESULT.md` 说明。
4. 只读取任务“必须读取”和“允许读取/修改”的文件。不要主动加载所有 Markdown 文档或整个数据库。
5. 将 `TASK.md` 状态改为 `in_progress`。

## 2. 修改规则

- 基于现有实现做最小改动，不重写项目。
- 只修改任务明确允许的文件。
- 不删除历史岗位、隔离证据、失败记录、用户画像或运行记录。
- 不修改 `.env`，不读取、输出或记录 API Key、Cookie、Token。
- 不运行 `git reset --hard`、`git checkout --`、递归删除或批量覆盖命令。
- 不安装新依赖，除非任务明确允许。
- 没有实际工具证据时写 `UNKNOWN`、`NEED_SKILL` 或 `NEED_CONNECTOR`，禁止声称已经执行。
- 不启动真实招聘网站采集，不访问外部招聘网站；只有任务明确标注 `允许外部访问：是` 才能访问指定来源。
- 遇到 403、429、验证码、安全验证、登录墙立即停止，不尝试绕过。
- 招聘类型只允许 `全职`、`实习`；无法确定时必须拒绝或隔离，不能猜成全职。
- AI 不得编造公司、城市、学历、职位描述、任职要求或投递链接。

## 3. 测试规则

先运行任务中的专项验证，再运行任务要求的全量验证。测试失败时只修复当前任务直接造成的问题；发现无关问题则记录，不顺手重构。

默认项目命令：

```powershell
& .\.venv\Scripts\python.exe -m compileall -q app crawler tests
& .\.venv\Scripts\python.exe -m unittest discover -s tests -p 'test_*.py' -q
node --check static/app.js
node --check static/admin-sources.js
```

不要为了让测试通过而降低质量门禁、删除测试或修改历史数据。

## 4. 完成回执

任务完成或阻塞后必须填写 `workbuddy/RESULT.md`：

- 任务编号和最终状态；
- 修改文件；
- 每项改动；
- 实际运行的命令及结果；
- 未解决问题；
- 是否访问外部网站；
- 是否修改数据库；
- 建议 Codex重点检查的位置。
- 修改前基线、修改后结果和任务编号，确保可以回溯。

完成时把 `TASK.md` 状态改为 `done`；无法继续时改为 `blocked`。不要把状态改为 `accepted`，该状态只能由 Codex设置。

## 5. 停止条件

出现以下任一情况，停止修改并写 `RESULT.md`：

- 任务要求之外的大规模重构才可能完成；
- 需要外部账号、验证码、密钥或用户隐私数据；
- 需要删除、覆盖或迁移现有岗位数据库；
- 允许修改的文件不足以完成任务；
- 需求存在两种会明显改变产品行为的解释；
- 连续两次修复后仍无法通过同一项测试。
